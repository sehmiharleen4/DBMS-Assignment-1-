Graph Traversal vs Relational Recursion

What Published Benchmarks Show & The Architecture of Graph Reachability

Speaker: S1 Harleen Kaur
Allocated: 75 seconds (0:00 - 1:15)
The "People You May Know" Problem

Multi-hop relationship expansion is the central computational primitive in modern connected applications:

  • Social Recommendations: Find friends-of-friends ($k=2,3$) while excluding existing friends to rank mutual connections.
  • Anti-Fraud Rings: Financial institutions trace accounts sharing phone numbers, IP addresses, or device IDs within 3 hops of flagged bad actors.
  • Supply Chain Impact: Tracing tier-3 and tier-4 supplier component failures propagating up to original equipment manufacturers.
Key Traversal Metric: Bound $k \in \{1, 2, 3, 4\}$ on scale-free graphs where vertex degree follows power-law distributions.
Two Divergent Database Philosophies
1. Native Graph Stores (Neo4j)

Relationships are first-class physical pointers. Employs Index-Free Adjacency (IFA): neighbors are traversed in $O(1)$ pointer operations independent of total graph edge count.

2. Relational DBMS (PostgreSQL 16)

Adjacency table friendship(src, dst) indexed via $B$-tree. Traversal requires repeated joins ($O(\log |E|)$ per hop) or WITH RECURSIVE CTE iterations.

Research Focus: Do commercial graph claims of "1000x faster traversal" hold when compared against optimized, indexed relational query formulations?

The Core Problem Statement

While graph database vendors claim orders-of-magnitude advantages for multi-hop graph queries, empirical literature reveals highly conflicting results depending on query formulation, caching, and hardware constraints. We investigate what published literature conclusively proves and formulate a rigorous benchmark to isolate these mechanisms.

RQ1: Data Models & Languages

Models & Declarative Syntax

How do the Property Graph and RDF models differ structurally and semantically, and how do Cypher, ISO GQL (2024), and SQL/PGQ (2023) express multi-hop traversal?

Key focus: Labeled Property Graphs vs Triples & GQL Standardization.
RQ2: Storage & Joins

Traversal Mechanics

How do native graph stores eliminate join overhead via Index-Free Adjacency (IFA), and how can relational engines counter this via Recursive CTEs and Level-wise joins?

Key focus: Direct pointer chasing vs $B$-Tree index scan loops.
RQ3: Benchmark Synthesis

Empirical Literature

What do published benchmarks reveal regarding multi-hop latency scaling, and does existing literature answer the specific Neo4j vs PostgreSQL friends-of-friends question?

Key focus: Kotiranta (2022) & Hohenstein (2019) synthesis.

The 2023–2024 Standardization Breakthrough

    MATCH (p:Person {id: $s})-[:FRIEND*1..3]-(f:Person)
  • ISO/IEC 39075:2024 (GQL): The first new standalone ISO database language since SQL in 1987. Formalizes declarative pattern matching and graph schema definitions across vendors.

Formulation A: PostgreSQL CTE

Recursive CTE with UNION

WITH RECURSIVE r(id, depth) AS ( SELECT dst, 1 FROM friendship WHERE src = :s UNION SELECT f.dst, r.depth + 1 FROM r JOIN friendship f ON f.src = r.id WHERE r.depth < :k ) SELECT count(DISTINCT id) FROM r WHERE id <> :s;

UNION removes duplicate (id, depth) tuples to halt cycle infinite recursion.

Formulation B: Level-Wise Joins

Chained Joins with Intermediate Deduplication

WITH l1 AS (SELECT DISTINCT dst FROM friendship WHERE src = :s), l2 AS (SELECT DISTINCT f.dst FROM l1 JOIN friendship f ON f.src = l1.id), l3 AS (SELECT DISTINCT f.dst FROM l2 JOIN friendship f ON f.src = l2.id) SELECT count(*) FROM ( SELECT id FROM l1 UNION SELECT id FROM l2 UNION SELECT id FROM l3 ) u WHERE id <> :s;

Prunes intermediate frontiers at each level, preventing combinatorial explosion.

Formulation C: Neo4j Cypher

Variable-Length Traversal Pattern

MATCH (p:Person {id: $s}) -[:FRIEND*1..3]-(f:Person) WHERE f <> p RETURN count(DISTINCT f) AS c;

Traverses relationships via Index-Free Adjacency pointers. Note: Cypher's relationship uniqueness can enumerate paths unless optimized by the query planner.

The BFS Ground-Truth Oracle

Before evaluating timing, all query formulations were validated against an independent mathematical oracle (code/selftest.py):

  • Baseline Generator: Deterministic Barabási-Albert graph ($N=600, m=3$, 1,791 edges).
  • Reference Implementation: Independent Python BFS using collections.deque with strict visit tracking.
  • Validation Scope: Tested all 4 depths ($k \in \{1, 2, 3, 4\}$) across 17 seed vertices (every 37th node) for both CTE and Level-wise queries.
  • Result: 136 / 136 checks passing with exact count parity ($0$ discrepancies). Proves query semantic equivalence!
$ python code/selftest.py selftest OK: 136 query results match the BFS oracle (n=600, edges=1791)
Strict Experimental Controls
  • Symmetrical Modeling: Undirected edges stored as two directed rows in PostgreSQL with clustered composite Primary Key (src, dst). Stored once in Neo4j with bidirectional traversal.
  • Resource Quotas: Pinned CPU cores (4 cores) and memory ceilings (6 GB) in Docker Compose to eliminate noisy-neighbor hardware bias.
  • Cache Warm-Up: Mandatory untimed warm-up execution per (depth, start) pair prior to 5 timed repetitions to stabilize buffer pool / pagecache.
  • Statistical Metrics: Latency recorded at Median and p95; strict 60s statement timeout to trap runaway Cartesian expansions.

Hohenstein & Jergler (2019) & Hypotheses
Index Sensitivity on 5-Hop Traversal:

PostgreSQL tested on 500,000 nodes (50 edges/node). Latency dropped from 60.25 s without an index to 6.43 s with an index on warm run (>9x speedup)!

Literature Verdicts on Hypotheses H1–H4:
  • H1 ($k=1$ parity): Supported. B-tree root lookup is comparable to IFA pointer dereference for single hops.
  • H2 (CTE latency growth): Supported. Naive recursive CTEs suffer from cycle re-expansion without intermediate pruning.
  • H3 (Level-wise mitigation): Supported. Chained joins with intermediate DISTINCT prune frontier explosion.
  • H4 (Hub degradation): Supported. High-degree roots trigger massive frontier fan-outs across all database engines.
Critical Synthesis: Published metrics demonstrate that database rankings are workload-dependent, not universal. Neither engine holds an unconditional superiority across all graph queries.

Threats to Validity, Conclusions & Future Work

Summary of Findings, Experimental Limitations & Next Research Horizons

Speaker: S4 Harmanparteek Singh
Allocated: 60 seconds (9:00 - 10:00)
Threats to Validity
  • Internal Validity (Cache Effects): In-memory warm cache benchmarks favor engines with low pointer overhead; cold storage I/O paging patterns may tell an entirely different story.
  • Synthetic vs Real Topologies: Barabási-Albert reproduces degree skew (power law) but underestimates the high clustering coefficients and community triadic closures of real social networks.
  • Query Semantics: We evaluate reachability count (distinct vertices). A path-returning query forces combinatorial path enumeration ($d^k$), shifting the cost profile.
Conclusions & Future Work
  • No Universal Superiority: Index-Free Adjacency is advantageous for unbounded graph explorations, but modern indexed relational engines match or surpass it on bounded recursive queries and aggregations.
  • Formulation Matters Most: Relational performance depends critically on query design (level-wise deduplication beats naive CTEs).
  • Immediate Next Step: Execute the containerized benchmark suite on bare-metal hardware and record live EXPLAIN ANALYZE execution plans.
  • Standards Horizon: Benchmark the emerging ISO SQL:2023 Part 16 (SQL/PGQ) when native PostgreSQL implementations stabilize.
